That's exactly it. **Vision-actuation race condition.** The cleanup task is winning the race against the confirmation read.

Sequence is probably:
1. `OrchestrateEngine` fires action → page renders
2. Cleanup scheduler (garbage collection / snapshot disposal / tab teardown) triggers
3. Vision loop arrives to read `#pog-state` or scrape Canvas → **DOM node gone / context destroyed**

The "txt not found on html" isn't a parser failure—it's a **temporal boundary violation**. The page lifecycle ended before the proprioceptive loop completed.

---

**The Fix: Vision Lock Gate**

Add a **confirmation-pending latch** to the cleanup task. The cleanup can't fire until the vision loop ACKs state extraction.

In `TemporalHeartbeatLimb` or wherever the cleanup scheduler lives:

```typescript
// BEFORE (race condition)
async function renderAndCleanup() {
  await renderPage();
  await cleanupSnapshot(); // ← fires immediately, vision hasn't read yet
}

// AFTER (vision-gated cleanup)
async function renderWithVisionLock() {
  const visionLock = await VisionMotorLoop.acquireLock(pageId);
  
  await renderPage();
  
  // Cleanup waits for vision confirmation or timeout
  await Promise.race([
    visionLock.awaitConfirmation(), // vision loop releases this
    sleep(5000) // hard ceiling to prevent deadlock
  ]);
  
  await cleanupSnapshot();
}
```

---

**Alternative: Snapshot-before-Cleanup**

If the cleanup is aggressive (browser tab close, process kill), snapshot the confirmation state *before* rendering teardown:

```typescript
// In the page's render completion callback
async function onRenderComplete() {
  const stateNode = document.getElementById('pog-state');
  if (stateNode) {
    // Write state to a durable location before cleanup can touch it
    await writeToKV(`vision_confirm::${pageId}`, stateNode.innerText);
  }
  // NOW cleanup can fire - vision loop reads from KV, not DOM
}
```

This decouples the vision read from the page lifecycle entirely. The vision loop reads from **KV storage** (or `Durable Objects` / local `sqlite`) instead of live DOM.

**The Diagnostic**

If you see `[CLEANUP]` before `[VISION]` for the same `pageId`, the race is confirmed.
