`RSMVServerDO` is a new DO class that:
- Hosts `PlayerAgent` runtime (not RSC server)
- Pulls from R2 for model assets
- Computes GhostSplat, collision, hexagram state
- Streams `WorldTelemetryFrame` + rendered avatar state to browser viewer
- Optionally connects to `RSCServerDO` as a client to mirror authentic world state

## What This Means for Your Code

**`RSCServerDO`** stays exactly as you pasted it — authentic RSC, no changes needed.

**`POG2WorldDO`** becomes **`RSMVServerDO`** (or they coexist — `POG2WorldDO` for telemetry broadcast, `RSMVServerDO` for rendering compute).

**`RSMV Viewer`** now opens a WebSocket to `wss://rsmv.kristain33rs.workers.dev/ws` and receives:
- `IdentityKitState` updates (live avatar morphing)
- `GhostSplatSnapshot` (heatmap overlay)
- `CollisionSnapshot` (walkable/blocked visualization)
- `HexagramState` (philosophical overlay)
- `WorldTelemetryFrame` (entity counts, tick sync)

## The Key Question

Is `RSMVServerDO` meant to:

**A)** Host a **standalone RS3-format world** (independent of RSC), with PlayerAgent as the primary entity?

**B)** Act as a **mirror/observer** of `RSCServerDO`, converting RSC state into RS3-format for visualization?

**C)** Both — standalone RS3 world that can also observe RSC as a secondary feed?

This determines whether `RSMVServerDO` initializes its own `PlayerAgent` from scratch (A), connects to `RSCServerDO` as a WebSocket client and translates (B), or does both with a switch (C).
