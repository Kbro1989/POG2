## The 66×66 Predictive Window

This is the **Sovereign Predictive Window** — a buffer centered on the avatar that pre-fetches:

```typescript
// In POG2WorldDO or RSMVServerDO:
const PREDICTIVE_WINDOW = 66; // tiles
const HALF_WINDOW = 33;

function getWindowBounds(avatarX: number, avatarY: number) {
  return {
    minX: avatarX - HALF_WINDOW,
    maxX: avatarX + HALF_WINDOW,
    minY: avatarY - HALF_WINDOW,
    maxY: avatarY + HALF_WINDOW
  };
}

// Pre-fetch:
// 1. Grounding manifests from D:\POG2\public (or R2)
// 2. Authentic spawns for mapsquares in window
// 3. Collision data for those mapsquares
// 4. Entity cache data for visible NPCs/objects/items
```

This is already partially implemented in `SovereignGroundingStream.ts` — it loads chunk manifests. The overlay just needs to **visualize** what the stream already loads.

## What's Missing from the Plan

1. **Server-side entity resolution** — `POG2WorldDO` currently broadcasts raw entity counts. It needs to stream **resolved entity packets** (name, stats, sovereignId) per tick. This requires integrating `PedagogyLimb` into the DO.

2. **ItemBook integration** — The plan mentions `ItemBook.ts` but doesn't specify how the HUD queries it. Is ItemBook a local JSON file, a KV store, or a query to the pedagogy model?

3. **pog2-pedagogy model access from viewer** — If the model is local (Ollama), the browser can't reach it. The DO must query the model and stream results. If the model is cloud (Workers AI), the viewer could query directly but that's slow.

4. **Performance budget** — 66×66 collision grid = 4,356 tiles. Rendering 4,356 wireframe boxes every frame is expensive. Need `InstancedMesh` or compute shader.

## My Recommendation

Implement in this order:

1. **`SovereignGroundingOverlay.ts`** first — collision is deterministic, no async dependencies, easiest to verify
2. **`SovereignSplatRenderer.ts`** second — depends on GhostSplatSnapshot from server, but heatmap format is stable
3. **`SovereignTrainingHUD.tsx`** third — depends on entity resolution pipeline (most complex)
4. **Server-side entity resolution** in parallel — integrate pedagogy model into `POG2WorldDO` tick loop
