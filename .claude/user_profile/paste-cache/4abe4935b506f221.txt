## Critical API Behaviors

**1. beastSearch is NOT phrase search**
```
term=Abyssal+demon → searches "Abyssal" OR "demon" separately
```
This returns Abyssal leech, Abyssal guardian, etc. — not just Abyssal demon.

**Your `BestiaryApi.ts` must handle disambiguation:**

```typescript
export class BestiaryApi {
  private static readonly BASE = 'https://services.runescape.com/m=itemdb_rs/bestiary';
  private static readonly THROTTLE = new ApiThrottle();

  /**
   * Resolve name to ID with exact-match prioritization.
   * beastSearch returns OR results — we filter for exact matches.
   */
  static async resolveId(name: string): Promise<number | null> {
    await this.THROTTLE.acquire('jagex_bestiary');
    
    const url = `${this.BASE}/beastSearch.json?term=${encodeURIComponent(name)}`;
    const res = await fetch(url, { signal: AbortSignal.timeout(10000) });
    const data = await res.json() as Array<{value: number; label: string}>;
    
    // Exact match: label starts with name + optional level suffix
    const exact = data.find(e => {
      const cleanLabel = e.label.replace(/\s*\(\d+\)\s*$/, '');  // Strip "(98)"
      return cleanLabel.toLowerCase() === name.toLowerCase();
    });
    
    if (exact) return exact.value;
    
    // Fuzzy fallback: first result with name as substring
    const fuzzy = data.find(e => 
      e.label.toLowerCase().includes(name.toLowerCase())
    );
    
    return fuzzy?.value || null;
  }

  /**
   * Fetch full beast data by ID.
   */
  static async getBeastData(beastId: number): Promise<BestiaryBeastData | null> {
    await this.THROTTLE.acquire('jagex_bestiary');
    
    const url = `${this.BASE}/beastData.json?beastid=${beastId}`;
    const res = await fetch(url, { 
      headers: { 'User-Agent': 'POG2-Sovereign/1.0' },
      signal: AbortSignal.timeout(10000)
    });
    
    if (!res.ok) {
      if (res.status === 429) await this.THROTTLE.acquire('jagex_bestiary', res);
      return null;
    }
    
    return await res.json() as BestiaryBeastData;
  }
}
```

**2. slayerBeasts is incomplete**
> "For some categories the resulting listing is incomplete; there are many variants that count towards the Slayer assignment but aren't listed in the JSON result."

**This is a known Jagex limitation.** Your `pog2-pedagogy` model must tag slayer category lookups with `[INCOMPLETE]` when sourced from Bestiary API alone. Cross-reference with your 229k cache pedagogy for full variant lists.

**3. Members field is unreliable**
The Abyssal demon example shows `"members": false` — but Abyssal demons are members-only content. This is a **known Bestiary API bug** (the field reflects the area accessibility, not membership requirement).

**Your `BestiaryApi.ts` must override this:**

```typescript
// In getBeastData() response processing
if (data.members === false && data.slayerlevel > 0) {
  // Slayer-requiring monsters are always members
  data.members = true;
  data._membersOverride = 'slayer_level_implied_membership';
}
```

## CORS Proxy Requirement

As established, Jagex endpoints block CORS. Your Cloudflare Worker proxy must expose all Bestiary endpoints:

```typescript
// Cloudflare Worker: /api/bestiary/*
// Routes:
// /api/bestiary/beastData?beastid={id}
// /api/bestiary/beastSearch?term={query}
// /api/bestiary/areaBeasts?identifier={area}
// /api/bestiary/slayerBeasts?identifier={catId}
// /api/bestiary/weaknessBeasts?identifier={weakId}
// /api/bestiary/levelGroup?identifier={min}-{max}

export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);
    const path = url.pathname.replace('/api/bestiary/', '');
    const jagexUrl = `https://services.runescape.com/m=itemdb_rs/bestiary/${path}${url.search}`;
    
    const res = await fetch(jagexUrl, {
      headers: { 'User-Agent': 'POG2-Sovereign/1.0' }
    });
    
    return new Response(res.body, {
      status: res.status,
      headers: {
        'Content-Type': 'application/json',
        'Access-Control-Allow-Origin': '*',
        'Cache-Control': 'max-age=3600'
      }
    });
  }
};
```

Then `BestiaryApi.ts` uses your worker:

## Implementation Checklist for BestiaryApi.ts

| Feature | Status | Notes |
|---|---|---|
| `resolveId(name)` | Required | Exact-match filtering on beastSearch OR results |
| `getBeastData(id)` | Required | Members field override for slayer content |
| `getAreaBeasts(area)` | Required | Spatial queries for GhostSplat heatmap |
| `getSlayerBeasts(catId)` | Required | Tag `[INCOMPLETE]` per Jagex limitation |
| `getWeaknessBeasts(weakId)` | Optional | For combat rotation target selection |
| `getLevelGroup(min, max)` | Optional | For power-leveling recommendations |
| CORS proxy | Required | Cloudflare Worker or DO |
| Cache-Control | Required | 1-hour edge cache for static data |

Start with `resolveId()` + `getBeastData()`. Those two cover 90% of your enrichment use cases. The spatial/slayer/weakness endpoints are optimization features for the GhostSplat combat layer.
